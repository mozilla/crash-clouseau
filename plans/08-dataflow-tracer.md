# 08 — Senior #4: Data-flow Tracer

## Objective
For one `(candidate patch, crash frame)` pair, fetch the actual source of the functions along the verified call path (`searchfox-cli define`) plus the candidate's raw unified diff, and have a mid/strong-tier LLM reason about whether the change can **free / mutate / null / overrun** the value the crash site dereferences — the data-flow inference searchfox's edge graph cannot express. It emits a structured, fully-cited `DataFlowHypothesis` (or a "no plausible data flow" verdict) that the Skeptic re-checks and the Principal consumes. This is the read-and-reason step that replaces the maintainer's brain.

## Scope
**In scope**
- A `trace_dataflow(dossier, candidate, path)` entry point that, per `(patch, frame)` pair, gathers function bodies, attaches them to the diff, and runs one `llm_call(role="data_flow_tracer", ...)` with a strict JSON-schema output.
- Building the prompt context: pull bodies for each hop on the call path via `searchfox-cli define`; fetch the candidate raw diff (`RawRevision.get_revision(channel, node)`); map the candidate's changed line numbers (`Changeset.added_lines/deleted_lines/touched_lines`) into the diff hunks so cites are exact.
- Defining the `DataFlowHypothesis` Pydantic model and writing it into the dossier (`candidate.dataflow`).
- Identifying the *mechanism class* (UAF / null-deref / mutate-after-pass / OOB) and the *target value* (the object/field the crash site touches), each with a source-line citation (file, function symbol, line, searchfox permalink).

**Out of scope (owned elsewhere)**
- The searchfox-cli Python adapter (subprocess wrapper, permalink/symbol-id capture) — owned by the Call-graph Explorer sub-plan; this unit *calls* `searchfox.define(...)`.
- The `llm_call(role, ...)` abstraction, model-per-role config, Pydantic-`messages.parse` plumbing, prompt-cache wiring — owned by the LLM-abstraction sub-plan; this unit only registers the `data_flow_tracer` role and supplies prompt + output model.
- The crash brief (mechanism class at the crash site, faulting address, expanded inlines) — produced by the Crash Interpreter; this unit *reads* `dossier.crash_brief`.
- The candidate set, neighborhood, call-path edges, and the "what changed semantically" one-liner — produced by Call-graph Explorer + Patch Scout; this unit reads `candidate.call_path` and `candidate.diff`.
- Independent re-verification of every claimed line/edge — owned by the Skeptic.
- The final verdict / abstain / needinfo draft — owned by the Principal.
- Dossier persistence table and the RQ worker chaining — owned by the worker/persistence sub-plan; this unit is a pure function over a dossier object.

## Deliverables
**Create**
- `crashclouseau/agent/dataflow.py`
  - `DataFlowHypothesis` (Pydantic) — fields: `verdict` (`Literal["plausible","implausible","insufficient"]`), `mechanism` (`Literal["uaf","null_deref","mutate_after_pass","oob","double_free","uninitialized","other"]`), `target_value` (str — the object/field the crash site touches), `target_citation` (`Citation`), `summary` (str — the one-paragraph causal sentence), `evidence_lines` (list of `Citation` — the diff lines + body lines that support the claim), `consistency_with_crash` (str — how it matches `crash_brief` mechanism/address), `confidence` (`Literal["low","medium","high"]`), `caveats` (list of str — revision drift, missing edge, indirect dispatch). All objects `additionalProperties:false`, no `minLength`/`maxLength`/`minimum`/`maximum`, no recursion (Claude structured-output JSON-schema limits). `Citation` reused from `dossier.py`.
  - `trace_dataflow(dossier, candidate, path_index=0) -> DataFlowHypothesis` — orchestrates body-gathering + prompt + `llm_call`, validates, attaches to `candidate.dataflow[path_index]`, returns it.
  - `_gather_path_bodies(call_path, repo) -> list[FunctionBody]` — for each hop function symbol, call `searchfox.define(...)`; cap count/size by config; record permalink+symbol-id per body; tolerate `define` misses (record as a caveat, don't fail).
  - `_anchor_diff(candidate, files) -> list[DiffHunkCite]` — read the candidate's hunk text + line cites from the patch-extraction foundation (`#14`, `agent.patch_extract.extract(node, channel)`) — **no independent `RawRevision` fetch here** — and tag each with `Changeset.added_lines/deleted_lines/touched_lines` to produce `(file, line, "added|deleted|touched", text)` cites.
  - `_build_prompt(crash_brief, candidate, path_bodies, diff_hunks)` -> system + user message blocks (volatile pair last; shared crash brief + diffs as the cacheable prefix via `cache_control` set by `llm_call`).
- `tests/agent/test_dataflow.py` — schema-validity, body-gathering fallbacks, diff-anchoring, and a recorded/mocked `llm_call` golden case (UAF: `Release(mObj)` moved before early return).

**Modify**

## Interfaces
**Reads (dossier in):**
- `dossier.crash_brief` — mechanism class at the crash site, faulting/poison address, `moz_crash_reason`, expanded inlines, the crashing frame (file/function/line). The Tracer's "target value" and "consistency" are checked against this.
- `candidate.node` / `candidate.bug` / `candidate.author` — provenance (from `Node`; note `Node.hgauthor` is an FK id, so the human-readable author string is resolved upstream and surfaced as `candidate.author`).
- `candidate.call_path` — ordered list of `CallEdge`s (each with a searchfox citation) from a stack frame to the changed function; the function symbols to `define`.
- `candidate.diff` — Patch Scout's per-file changed-function summary + line numbers (originating from `patch.parse` / `Changeset.*_lines`).

**Writes (dossier out):**
- `candidate.dataflow[path_index] = DataFlowHypothesis` — the cited hypothesis. A hypothesis whose `evidence_lines` is empty or whose citations lack permalinks/symbol-ids is **invalid** and must be coerced to `verdict="insufficient"` (grounding rule §6/§2).

**Depends on:** patch-extraction foundation (`#14`, hunk text + line cites), Dossier-contract sub-plan (types), LLM-abstraction sub-plan (`llm_call`, role config, caching, `parse`), Call-graph Explorer sub-plan (`searchfox.define` adapter + `call_path`), Patch Scout (`candidate.diff`), Crash Interpreter (`crash_brief`).
**Feeds:** Skeptic (re-checks each `evidence_line` against diff/index) and Principal (consumes the surviving hypothesis in the per-candidate dossier).

## Implementation steps
1. Confirm/await the dossier contract: import `Dossier`, `Candidate`, `CallEdge`, `Citation`, and the `crash_brief` shape from `crashclouseau/agent/dossier.py`. If not yet landed, stub a minimal `Citation` (file, symbol_id, permalink, line, text) and a `Candidate` protocol to develop against; replace with the real import on merge.
2. Define `DataFlowHypothesis` per the schema-limit rules (no `minLength`/`maxLength`/`minimum`/`maximum`, no recursion; `additionalProperties:false` on every object; `Literal` enums). Keep it flat — citations are a list of the shared `Citation` type. (The Python `anthropic` SDK strips unsupported constraints client-side, but author the model without them to keep the schema honest.)
3. Implement `_anchor_diff`: fetch the raw unified diff for `candidate.node` via `RawRevision.get_revision(channel, candidate.node)` (NOT `get_url`, which returns only the base `/raw-rev` URL), and align it with `Changeset.added_lines/deleted_lines/touched_lines` (read from the `Changeset` row for the candidate node) so each cited hunk line carries an exact file+line+kind+text. Handle `isnew` changesets (whole file added) as a single "new file" cite.
4. Implement `_gather_path_bodies`: for each `CallEdge` function symbol on `candidate.call_path`, call `searchfox.define(symbol, repo=<channel-repo>)`; cap at `max_path_bodies`, truncate each body to `max_body_chars`, and record the permalink + symbol-id. On a `define` miss (virtual/macro/template/cross-language — §7), append a caveat string and continue. Prefer truncating around the changed line range (using `Changeset.*_lines`) over head-truncation so the relevant code survives (see Risks).
5. Implement `_build_prompt`: system message states the role, the grounding rule ("cite source lines and diff lines; if you cannot ground the data flow, return `insufficient`"), and the revision-drift warning (the candidate patch is itself part of what differs between the crashed build and indexed source). User message = cacheable prefix (`crash_brief` + full candidate diff) followed by the volatile pair-specific block (the one `(patch, frame)` target + gathered bodies) last, so caching is effective. The cacheable prefix must clear the model's minimum (2048 tok for Sonnet 5, 4096 for Opus 4.8) or it silently won't cache.
6. Wire `trace_dataflow`: assemble context, call `llm_call(role="data_flow_tracer", system=..., messages=..., output_format=DataFlowHypothesis)`; the LLM-abstraction layer resolves the model id (`claude-sonnet-5` default, `claude-opus-4-8` escalation), sets `thinking={"type":"adaptive"}` + `output_config.effort` (both Sonnet 5 and Opus 4.8 support effort and adaptive thinking — only Haiku 4.5 rejects `effort`), and applies `cache_control` on the prefix. This unit does not pass `effort`/`thinking` itself — it only supplies the role + prompt + output model.
7. Post-validate: if `evidence_lines` is empty, or any `Citation` is missing a permalink/symbol-id (for body lines) or a diff anchor (for diff lines), downgrade `verdict` to `insufficient` and log. Attach to `candidate.dataflow`.
8. Add `agent.dataflow` config block + a `config.get_dataflow_cfg()` accessor (or reuse the LLM sub-plan's accessor). `config.py` currently has no `get_agent_*` helper, so one must be added.
9. Tests: a mocked-`llm_call` golden case reproducing the PLAN's example (`Release(mObj)` moved before an early return causes UAF derefed at frame0); a `define`-miss case asserting a caveat + non-crash; a diff-anchoring unit test (mocking `RawRevision.get_revision` and a `Changeset` row); a schema-rejection test (uncited claim -> `insufficient`).
10. Run `flake8`/`black` to match repo style; ensure no module-import side effects (config/`db` not touched at import time, consistent with `worker.py`/`config.py`).

## Risks & open questions
- **Searchfox revision drift (§7).** `define` returns ~tip bodies, not the crash build node's source. The changed function may differ from what crashed. Mitigation: pass drift as an explicit caveat and instruct the model to prefer the *diff* (which is build-accurate via `RawRevision.get_revision`) over the indexed body when they conflict, and to lower confidence when only the indexed body supports a claim.
- **Call-graph holes (§7).** If `call_path` is missing the decisive hop (virtual/IPC/FFI), the data flow is unprovable -> must return `insufficient`, not guess. Confirm Call-graph Explorer marks indirect edges so the Tracer can caveat them.
- **Body size vs. context/cost.** Hot functions can be huge; `max_body_chars` truncation may cut the relevant code. Resolution (step 4): truncate around the changed line range using `Changeset.*_lines` rather than head-truncating.
- **Model tier.** Sonnet 5 vs Opus 4.8 for this role is a Phase-0/Phase-4 tuning question (PLAN §5, §9); keep it pure config. Haiku 4.5 is explicitly too weak here and rejects the `effort` parameter (and has no extended thinking) — do not allow it as the default for this role.
- **`patch.parse` vs raw diff duplication — resolved by `#14`.** The patch-extraction foundation is the single source of hunk text + line cites; `_anchor_diff` reads from it rather than re-fetching `RawRevision`. FLAT line numbers (`patch.parse` / `Changeset.*_lines`) remain the source of the added/deleted/touched kind tag.
- **`Changeset.find` shape.** `find` returns `{filename: [node, ...]}`, not `Changeset` rows — to read the `*_lines` arrays for a candidate node, fetch the changeset row by node (the candidate set / Patch Scout already do this upstream; confirm the row is reachable from `candidate`).
- **searchfox-cli "define" surface unverified here.** The exact subcommand name and flag spelling for full-function source extraction live behind the Call-graph Explorer adapter; this unit must not assume them. If the adapter's `define(symbol, repo)` signature differs, adapt at that boundary only.
- **Multiple paths per candidate.** A candidate may connect to several frames. `path_index` handles one; the orchestrator (worker sub-plan) decides how many paths to trace per candidate within budget.

## Acceptance criteria
- `trace_dataflow(dossier, candidate)` returns a schema-valid `DataFlowHypothesis` for a real dossier; `client.messages.parse` never raises a validation error on the output (schema obeys Claude JSON-schema limits: `additionalProperties:false`, no `minLength`/`maxLength`/`minimum`/`maximum`, no recursion).
- Every `plausible`/`implausible` hypothesis carries at least one `Citation` that is either a diff anchor (file+line+kind from `RawRevision.get_revision`/`Changeset.*_lines`) or a body line (file+symbol-id+permalink from `searchfox.define`); a hypothesis without such citations is automatically `insufficient`. (Grounding rule, PLAN §2/§6.)
- The golden UAF test (`Release(mObj)` moved before early return; frame0 derefs freed `mObj`; matches poison address in `crash_brief`) yields `verdict="plausible"`, `mechanism="uaf"`, `target_value` naming `mObj`, and citations to both the moved diff line and the frame0 deref.
- A `define` miss / missing decisive edge yields `verdict="insufficient"` with a populated `caveats`, and never raises.
- The crash-brief + diff prefix is marked cacheable and the per-pair block is last (verifiable in the assembled messages structure), so repeated pairs on the same candidate hit the prompt cache (assuming the prefix clears the model's minimum cacheable length).
- Model id is read from `config.agent.dataflow.model` (defaults `claude-sonnet-5`); no model id string is hardcoded in `dataflow.py`.
- `flake8`/`black` clean; no DB or network access at import time; unit tests pass with `llm_call` and `searchfox.define` mocked (no live API/CLI calls in CI).
