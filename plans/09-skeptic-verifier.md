# 09 — Senior #5: Skeptic / verification pass

## Objective
The Skeptic is an adversarial verification senior that tries to *refute* each assembled evidence chain before it costs principal tokens. For every claim in a candidate dossier — each call edge, each cited diff line, each reachability assertion, and each "not backed out" assumption — it runs the cheapest check that can disprove it: deterministic DB/diff/regex checks first, then a Haiku 4.5 confirmation only where reasoning is unavoidable. It writes a `pass`/`fail`/`unverifiable` verdict per claim back into the dossier and kills chains whose load-bearing claims fail.

## Scope
**In scope**
- Consume each candidate's assembled chain (call path edges, diff-line cites, reachability, data-flow hypothesis summary) and emit a per-claim verification verdict + an overall chain `kill`/`keep` decision.
- Re-query searchfox-cli (`--calls-between` / `--calls-from` / `--define`) to independently confirm each *claimed call edge exists at the claimed revision* — never trust the Explorer's stored citation.
- Re-fetch the candidate diff (`RawRevision`) and confirm each *cited diff line number and quoted text* actually appear in that changeset's hunks (cross-check against `Changeset.added_lines/deleted_lines/touched_lines` in the DB).
- Deterministic DB checks: `Node.backedout` lookup, push-date / 30-day-retention sanity, revision-drift flag (build node vs searchfox tip).
- Reachability check: confirm the changed function is reachable from a stack frame via the claimed path at (or near) the revision.
- Emit `skeptic` notes into the dossier (per-claim verdicts + a one-line refutation reason on failure).

**Out of scope (owned by other sub-plans)**
- The Pydantic dossier schema and validation-at-handoff — owned by the dossier-contract sub-plan (Phase 1). Skeptic only *reads/writes* fields it defines.
- The `llm_call(role, ...)` abstraction, model-tier config, prompt caching, and the `anthropic` client — owned by the LLM-abstraction sub-plan. Skeptic only *calls* `llm_call("skeptic", ...)`.
- The searchfox-cli Python adapter (subprocess wrapper that captures permalinks/symbol-ids and owns the canonical flag spelling) — owned by the call-graph-explorer / searchfox-adapter sub-plan. Skeptic *imports and reuses* it; it does **not** hardcode searchfox-cli flags.
- Building the call path / diff cites / data-flow hypothesis in the first place — Explorer, Patch Scout, Data-flow Tracer.
- The final verdict and abstain decision — the Principal sub-plan. Skeptic only prunes inputs.
- RQ enqueue wiring from `update.py` and the orchestration job order — owned by the worker-orchestration sub-plan; Skeptic exposes a callable step.

## Deliverables
- **`crashclouseau/agent/skeptic.py`** (NEW) — the unit. Public surface:
  - `verify_chain(dossier: Dossier, candidate: Candidate) -> SkepticReport` — orchestrates all checks for one candidate's chain; returns per-claim verdicts + overall `keep`/`kill`.
  - `verify_call_edge(edge: CallEdge, repo: str) -> SkepticClaim` — re-runs `--calls-between`/`--calls-from` via the searchfox adapter; passes only if the claimed edge appears in fresh output.
  - `verify_diff_cite(cite: DiffCite, node: str, channel: str) -> SkepticClaim` — re-fetches the raw diff via the same `RawRevision` path `patch.py` uses, confirms the cited line number is in the changeset's added/deleted/touched set (DB cross-check via `Changeset`) **and** the quoted text matches the raw hunk.
  - `verify_backout(node: str, channel: str) -> SkepticClaim` — deterministic `Node.backedout` lookup (`fail` if backed out, since a backed-out patch is a weak culprit unless dossier flags otherwise).
  - `verify_reachability(edge_path, frames, node, channel) -> SkepticClaim` — confirms the changed function is reachable from a real `CrashStack` frame via the claimed path; flags revision drift (build node vs searchfox tip).
  - `_llm_confirm_quote(cite, raw_hunk) -> bool` — only fallback that uses `llm_call("skeptic", ...)` when a deterministic text match is ambiguous (e.g. whitespace/reflow); returns structured pass/fail via a strict Pydantic schema.
  - `apply_verdicts(dossier, reports) -> Dossier` — writes `skeptic` notes onto the dossier and drops killed candidates.
- **`crashclouseau/agent/dossier.py`** (MODIFY — coordinate with dossier sub-plan; this unit *adds* the Skeptic-output fields if not already present): `SkepticClaim {claim_id, kind: Literal["call_edge","diff_cite","backout","reachability"], verdict: Literal["pass","fail","unverifiable"], reason: str, refuted_by: str}` and `SkepticReport {candidate_node, claims: list[SkepticClaim], decision: Literal["keep","kill"]}`; a `skeptic: SkepticReport | None` field on `Candidate`. All models `additionalProperties:false`, no `minLength`/`maxLength`/`minimum`/`maximum`/recursion (Anthropic strict-schema limits).
- **`config/global.json`** (MODIFY) — add `agent.skeptic` block (kill-on-fail claim kinds, searchfox repo per channel, subprocess timeout, `max_unverifiable`).
- **`tests/test_skeptic.py`** (NEW) — unit tests with fixtured searchfox output, a fixtured raw diff, and DB fixtures for backed-out / non-backed-out nodes.

## Interfaces
**Reads (dossier fields):** per `Candidate`: `node`, `bug`, `author`, `channel`; `call_path: list[CallEdge]` (each with `from_symbol`, `to_symbol`, `depth`, searchfox citation/permalink, claimed `revision`); `diff_cites: list[DiffCite]` (each with `filename`, `line`, `quoted_text`, `change_kind`); `dataflow_hypothesis` (summary string, used only as context for the LLM quote fallback); `crash_brief` (shared cacheable prefix). Reads DB: `CrashStack.get_by_uuid` (returns `(res, uuid_info)`; frames in `res["frames"]`), `Node`, `Changeset`, `Score`.

**Writes (dossier fields):** `Candidate.skeptic: SkepticReport` (per-claim `verdict` + `reason` + `refuted_by`, overall `decision`). Removes/marks candidates whose `decision == "kill"`.

**Depends on (upstream sub-plans):** dossier-contract (schema), LLM-abstraction (`llm_call`, model config, caching), searchfox-adapter (subprocess wrapper + citation capture + canonical flag spelling + channel→repo mapping), Explorer/Patch-Scout/Tracer (they populate the chain Skeptic refutes).

**Feeds (downstream):** the Principal sub-plan consumes only `keep` candidates with their `skeptic` notes attached; the eval-harness sub-plan reads `skeptic` verdicts to compute evidence-correctness. The worker-orchestration sub-plan calls `verify_chain` after the Tracer and before the Principal.

## Implementation steps
1. Confirm the dossier schema exposes `CallEdge` (incl. claimed `revision` + citation), `DiffCite` (incl. `quoted_text` + `change_kind`), and that `Candidate` can carry a `skeptic` field; if not, add `SkepticClaim`/`SkepticReport` to `crashclouseau/agent/dossier.py` (strict-schema-compliant).
2. Add the `agent.skeptic` config block to `config/global.json` and a `get_skeptic_config()` accessor in `crashclouseau/config.py` (mirroring existing `get_*` helpers; default `kill_on_fail = ["call_edge","diff_cite","backout"]`, `searchfox_repo_by_channel = {"nightly":"mozilla-central","beta":"mozilla-beta","release":"mozilla-release"}` — note searchfox-cli has **no `autoland`** repo; nightly maps to `mozilla-central`, `subprocess_timeout`, `max_unverifiable`).
3. Implement `verify_backout` first (pure DB, no LLM, no network): `Node.get_id(node, channel)` returns a Row (or `None`) — treat `None` as "rev not in window" (retention/30-day boundary, cross-checked against `get_ndays_of_data()`); when present, read `backedout`.
4. Implement `verify_diff_cite`: re-fetch the raw unified diff via the same `RawRevision` path `patch.py` uses, and recompute the changed-line sets via `patch.parse()`; cross-check the cited `line` against `Changeset.added_lines/deleted_lines/touched_lines` for that `(node, filename)`; then verify `quoted_text` appears in the raw hunk. Pass only if both line-number and text agree; mark `unverifiable` (not `fail`) if the diff can't be fetched.
5. Implement `verify_call_edge`: call the searchfox adapter (`--calls-between` for path edges, `--calls-from` to confirm a single hop, `--define` to confirm the symbol resolves) against the repo from config for the candidate's channel (`mozilla-central`/`mozilla-beta`/`mozilla-release`); pass only if the claimed `(from_symbol -> to_symbol)` edge is present in *fresh* output. Capture the fresh permalink/symbol-id as evidence. Treat searchfox-cli nonzero exit / timeout as `unverifiable`, not `fail`. Do not hardcode flags — call the adapter's functions.
6. Implement `verify_reachability`: anchor to a real frame via `CrashStack.get_by_uuid` (use `res["frames"]` from the returned tuple); confirm the changed function is the terminus of a chain originating at a stack frame's function; compute the revision-drift flag by comparing the candidate `node` / build node (resolved via `inspector.get_path_node`/`git2hg`) against the searchfox tip the adapter reports. Drift alone → annotate, do not auto-fail.
7. Implement `_llm_confirm_quote` as the *only* LLM path: when step 4's text match is ambiguous, send the crash brief + raw hunk (cacheable prefix, `cache_control` ephemeral, ≥4096 tokens or it won't cache on Haiku 4.5) with the volatile cite/quote last to `llm_call("skeptic", output_format=...)`; force a strict boolean-plus-reason Pydantic result. Plain Haiku call (no `effort`, no thinking).
8. Implement `verify_chain` to run the deterministic checks (3,4,6) and the searchfox check (5) per claim, populate a `SkepticClaim` each, then compute `decision`: `kill` if any claim whose `kind` is in `kill_on_fail` has `verdict == "fail"`, or if `unverifiable` count exceeds `max_unverifiable`; else `keep`.
9. Implement `apply_verdicts` to attach `SkepticReport` to each `Candidate` and drop `kill` candidates from the dossier passed onward; log each refutation via `logger`.
10. Wire `verify_chain` as a step the agent RQ job calls between Tracer and Principal (the orchestration sub-plan owns the actual `enqueue_call(func=..., args=(...), result_ttl=0)`); ensure it runs inside the Flask app context like other `db.session` users and does not hold the session across the searchfox subprocess (cf. recent "Reset the DB session after each web request" / session-wedge fixes).
11. Add `tests/test_skeptic.py` with fixtures: a searchfox-cli output sample (edge present vs absent), a raw diff sample (cited line present/absent, text match/mismatch), and DB rows for a backed-out and a live node; assert `decision` transitions and that no LLM is invoked on the deterministic happy path.

## Risks & open questions
- **Revision drift makes searchfox edges legitimately absent.** searchfox-cli indexes ~tip per repo, not an arbitrary crash build node, so a real edge at the build node may not exist at searchfox tip (and vice-versa). Mapping `fail` here would over-kill; current plan treats a clean "edge absent + drift detected" as `unverifiable`, not `fail`. Open: do we ever `kill` on a missing edge, or only downgrade confidence and let the Principal abstain?
- **searchfox-cli call-graph holes** (virtual/indirect/function-pointer/template/macro and cross-language JS↔C++↔Rust edges, per PLAN §7): the Skeptic cannot *prove* a missing edge is truly missing. Must distinguish "refuted" from "not findable." `max_unverifiable` is the blunt knob; needs tuning in Phase 4 eval.
- **searchfox-cli repo coverage vs crash-clouseau channels.** searchfox-cli repos are `mozilla-central`/`mozilla-beta`/`mozilla-release`/`mozilla-esr*`/`comm-central` — there is **no `autoland`** tree. crash-clouseau's primary target is `nightly` → `mozilla-central`, which is fine, but any candidate whose changeset landed only on `autoland` (not yet merged to a searchfox-indexed repo) cannot be edge-verified → must be `unverifiable`, not `fail`.
- **Backout is not always disqualifying.** A patch can be backed out *after* the crashed nightly build but still be the culprit *for that build*. Open: compare `Node.pushdate` / backout date against the build date before failing on `backedout`; the simple boolean check may be too aggressive.
- **Diff text quoting fragility.** `parsepatch` FLAT mode gives only line numbers, so text confirmation needs the raw `RawRevision` diff; whitespace/encoding/CRLF differences could cause false `fail`s — hence the LLM quote fallback, but that reintroduces a (small) hallucination surface.
- **searchfox-cli flag spelling.** Commands are **flags** (`--calls-from`, `--calls-to`, `--calls-between`, `--define`), `--calls-between` takes a single comma-joined `<SOURCE,TARGET>` arg, `--depth` defaults to 1, and the repo flag is `--repo`/`-R`. The adapter sub-plan owns the canonical invocation; Skeptic must call its functions, not hardcode flags.
- **Cost.** Most checks are deterministic (free); the only token cost is the rare quote-disambiguation Haiku 4.5 call. Budget should stay near-zero per candidate — verify in eval.

## Acceptance criteria
- `verify_chain` returns a `SkepticReport` with exactly one `SkepticClaim` per dossier claim, each carrying `verdict ∈ {pass, fail, unverifiable}` and a non-empty `reason`/`refuted_by` on non-pass.
- A candidate whose claimed `(from -> to)` call edge does **not** appear in fresh searchfox-cli output (at a searchfox-indexed repo for its channel) is marked `fail` on that claim and the chain `decision == "kill"` (when `call_edge ∈ kill_on_fail`).
- A candidate citing a diff line that is absent from the re-fetched diff / not in `Changeset` changed-line arrays is `fail`; a candidate whose `quoted_text` matches the raw hunk at the cited line is `pass`.
- `Node.backedout == True` for the candidate node yields a `backout` claim `fail` (subject to the pushdate refinement above) and kills the chain.
- The deterministic happy path (valid edge, valid cite, not backed out, reachable) runs with **zero** `llm_call` invocations (assert via test mock).
- searchfox-cli timeout/nonzero-exit, an unindexed repo (e.g. autoland-only changeset), and unfetchable diffs produce `unverifiable`, never a false `fail`; chain is killed only if `unverifiable` count > `max_unverifiable`.
- Only `keep` candidates (with `skeptic` notes attached) are present in the dossier handed to the Principal; killed candidates are removed and each kill is logged.
- `tests/test_skeptic.py` passes under the existing test runner; verdict transitions are covered for edge-present/absent, cite-match/mismatch, backed-out/live, and drift cases.
