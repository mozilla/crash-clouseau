# 00 — Phase-0 Call-graph Explorer spike (go/no-go)

## Objective
Prove (or kill) the one assumption the whole evidence-agent rides on: that a cheap LLM driving `searchfox-cli` can build a call-graph *neighborhood* from a crash's stack frames that **reaches the true regressor function even when that function is off-stack**. We do this on a small hand-mined corpus of past Firefox-nightly regressions, as a throwaway standalone script with **no DB and no integration**, and report a single headline metric: **off-stack recall (call-graph neighborhood) vs. stack-only recall (today's baseline)**.

## Scope
**In scope**
- A standalone CLI script + a small frozen corpus JSON of historical off-stack nightly regressions.
- A thin `searchfox-cli` subprocess adapter (just enough to drive the `--calls-from`/`--calls-to`/`--calls-between`/`--define` flags and capture citations) — *throwaway quality*, not the production adapter.
- One cheap-LLM explorer loop (Haiku 4.5) that proposes which symbols/edges to expand; the script executes the searchfox queries and accumulates a neighborhood symbol set.
- Membership check: did the neighborhood contain the true regressor function(s)? Aggregate recall + a per-case trace log.

**Out of scope (owned by later sub-plans)**
- The production `searchfox-cli` adapter with permalink/symbol-id citation capture (Phase 1 dossier sub-plan).
- The Pydantic dossier contract, schema-validated hand-off (Phase 1).
- Crash Interpreter / Patch Scout / Data-flow Tracer / Skeptic roles as real agents, the principal verdict, abstain contract (Phases 1–2).
- The `llm_call(role, ...)` config-driven abstraction (LLM-abstraction sub-plan) — Phase 0 may inline a minimal `anthropic` call and a hardcoded model id.
- DB persistence, RQ wiring in `update.py`/`worker.py`, UI panel, needinfo prefill (Phase 3).
- The full eval harness (Batch API re-runs, evidence-correctness, abstain calibration) — Phase 4. Phase 0 measures *only* metric #1 (off-stack recall) from PLAN.md §8.

## Deliverables
Throwaway, isolated under a new `spike/` dir so nothing touches the production package:

- `spike/corpus.json` — frozen hand-mined corpus. List of objects:
  `{"clouseau_bug": int, "regressor_bug": int, "regressor_nodes": [hg_short_rev,...], "signature": str, "channel": "nightly", "build_window": {"start": "YYYYMMDD", "end": "YYYYMMDD"}, "off_stack": true, "notes": str}`.
- `spike/mine_corpus.py` — `main()` + `mine_clouseau_bugs(limit, since) -> list[dict]`, `regressor_of(bug) -> (regressor_bug, regressor_nodes)`, `signature_of(bug) -> str`. Uses `Bugzilla` to pull bugs blocking the `clouseau`-alias bug and their `regressed_by`/`cf_crash_signature`; emits/refreshes `corpus.json`. Designed to be run once and hand-curated (mark `off_stack`).
- `spike/searchfox_cli.py` — thin adapter: `calls_from(symbol, depth, repo)`, `calls_to(symbol, depth, repo)`, `calls_between(source, target, repo)`, `define(symbol, repo)`, `search(text, repo)`. Each shells out via `subprocess.run([...])` building the **flag** form (`["searchfox-cli", "--calls-from", symbol, "--depth", str(depth), "-R", repo]`; `calls_between` passes a single `f"{source},{target}"` arg; `search` uses `-q`); returns `{"raw_markdown": str, "symbols": [str], "permalinks": [str]}` (best-effort parse of the markdown). Returns empty on missing edges. NOTE: `--calls-between` operates on class/namespace pairs, so the adapter must be prepared for it to return nothing for plain function pairs. |
- `spike/regressor_funcs.py` — `changed_functions(node, channel) -> set[str]`: fetch the regressor diff via `RawRevision.get_revision(channel, node)`, parse `+++ b/<path>` and `@@ ... @@ <context>` headers, and confirm/resolve each touched function name against `searchfox_cli.define`/`search`. Returns the ground-truth target function set per regressor node.
- `spike/explore.py` — the explorer loop: `build_neighborhood(crash_frames, budget) -> {"symbols": set, "trace": [steps]}`. Seeds from the parsed crash frames (via `inspector`), asks Haiku 4.5 (strict-JSON query proposals) which symbols to expand next, executes them through `searchfox_cli`, accumulates symbols, stops at a query/token budget or fixpoint.
- `spike/run_spike.py` — CLI entrypoint: `python -m spike.run_spike --corpus spike/corpus.json [--model claude-haiku-4-5] [--budget-queries 40] [--out spike/results.json]`. For each corpus case: fetch crash → parse frames → compute `stack_only` symbol set (frame functions) and `neighborhood` set → check membership of each `regressor_funcs` target → write per-case + aggregate recall.
- `spike/results.json` + `spike/README.md` — the metric table (off-stack recall neighborhood vs stack-only), per-case traces, token/$ spend, and the explicit **go/no-go recommendation**.
- `requirements-spike.txt` — `anthropic`, `pydantic` (Phase-0 only; do **not** edit the production `requirements.txt`).

## Interfaces
**Inputs consumed**
- BMO: bugs blocking the `clouseau`-alias bug → `regressed_by`, `cf_crash_signature` (corpus ground truth).
- Socorro: `ProcessedCrash.get_processed(uuid)` JSON; `SuperSearch` to resolve signature→UUIDs within the build window. Per PLAN §4, the Crash Interpreter's raw material (`reason`, `crash_info.address`, `moz_crash_reason`, per-frame `inlines`/`trust`) is available — Phase 0 only needs `json_dump.threads[crashing_thread].frames` (function/file/line) plus `crash_info.crashing_thread`, obtained via `inspector.inspect_stacktrace(data, build_node)`.
- hg: `RawRevision.get_revision(channel, node)` raw diff of each regressor node.
- `searchfox-cli` markdown output (call edges + function bodies).

**Outputs produced**
- `spike/results.json`: per case `{clouseau_bug, regressor_bug, regressor_funcs, on_stack_funcs, neighborhood_size, regressor_in_stack: bool, regressor_in_neighborhood: bool, query_count, est_cost_usd}` + aggregate `{stack_only_recall, neighborhood_recall, n_cases}`.
- The go/no-go recommendation in `spike/README.md`.

**Dossier fields (read/write):** Phase 0 writes **no dossier fields** — the typed dossier doesn't exist yet (Phase 1). It *prototypes* one field only, informally: the "call path as a list of edges with searchfox citation" that the Phase-1 dossier (`call_path`/`neighborhood`) will formalize. The `searchfox_cli.py` permalink capture here is the seed of the Phase-1 production adapter's citation contract.

**Depends on:** nothing (first work unit; gates everything). **Feeds:** Phase 1 (dossier contract + Call-graph Explorer + Patch Scout) — but only if go. The corpus mined here is reused by the Phase-4 eval harness.

## Implementation steps
1. Create `spike/` dir and `requirements-spike.txt` (`anthropic`, `pydantic`); install into a throwaway venv **that also has `libmozdata>=0.2.12`** (libmozdata is NOT importable in this checkout — it lives only as a source copy at `/home/calixte/rm.backup/dev/mozilla/git/libmozdata` — so `pip install libmozdata` into the spike venv). Confirm `ANTHROPIC_API_KEY` is set and install `searchfox-cli` (it is NOT on `PATH` here — `searchfox-cli not found`).
2. **Mine the corpus** (`mine_corpus.py`): query BMO via `Bugzilla` for bugs whose `blocked` carries the `clouseau` alias (the bugs Clouseau itself filed); pull `include_fields=["id","regressed_by","cf_crash_signature","status"]`. For each, record `regressor_bug = regressed_by[0]` and `signature = cf_crash_signature`. Resolve `regressor_bug` → its landed nightly changeset node(s) (BMO bug → commit comments / hg pushlog; record short hg revs). Write `corpus.json`.
3. **Curate off-stack cases by hand:** for each candidate, fetch one representative crash UUID via `SuperSearch` (signature + `release_channel=nightly` + `product=Firefox` + build_id window from `pushdate`), parse frames with `inspector.inspect_stacktrace`, and compute `changed_functions(regressor_node)`. Keep only cases where the regressor function is **NOT** among the on-stack frame functions (`off_stack=true`). Target 6–10 solid cases. Freeze `corpus.json` (signatures persist even though crashes age out of the 30-day DB).
4. **Adapter** (`searchfox_cli.py`): wrap each operation as a **flag** invocation (`--calls-from`/`--calls-to`/`--calls-between`/`--define`/`-q`), `-R mozilla-central` by default; capture stdout markdown, best-effort extract symbol ids + permalinks. Return empty on no-edge (don't crash). Unit-smoke each command against one known symbol from a corpus case (e.g. `searchfox-cli --calls-from <Sym> --depth 2 -R mozilla-central`).
5. **Ground-truth extractor** (`regressor_funcs.py`): from the `RawRevision` raw diff, extract touched files + `@@` hunk context function hints; confirm each against `searchfox_cli.define`/`search` to get canonical function names. This set is the recall target.
6. **Explorer loop** (`explore.py`): seed neighborhood with on-stack frame functions; in a budgeted loop, send Haiku 4.5 the crash brief + current neighborhood (cache the stable prefix with `cache_control` ephemeral — but expect no cache benefit if the prefix is under 4096 tok) and force a strict-JSON list of next queries (`calls-from`/`calls-to`/`calls-between` + symbol + depth); execute via the adapter; merge returned symbols; stop at `--budget-queries` or fixpoint. Keep calls plain (no `effort`, no thinking — unsupported on Haiku 4.5). Log every (proposal → searchfox cmd → returned symbols) step.
7. **Runner + metric** (`run_spike.py`): for each case compute `stack_only` (frame functions) and `neighborhood`; check `regressor_funcs ⊆?` each; aggregate `stack_only_recall` and `neighborhood_recall`; record query count and estimated $ (Haiku 4.5 $1/$5 per 1M, count cached vs uncached input via `response.usage`). Write `results.json`.
8. **Optional A/B:** re-run the 2–3 lowest-recall cases with `--model claude-opus-4-8` to attribute misses to searchfox holes vs. cheap-model navigation. Note results; do not change the default.
9. Write `spike/README.md` with the metric table, the §7 blind spots actually hit (virtual/indirect/cross-language/macro/template misses, revision drift, `--calls-between` class-granularity limit), and a one-line **GO / NO-GO**.

## Risks & open questions
- **Searchfox holes sink the premise (the whole point of the spike).** Virtual dispatch, function pointers, IPC, templates, macros, and especially cross-language edges (JS→C++ WebIDL/XPIDL, Rust↔C++ FFI) are invisible to `--calls-to`/`--calls-from`. If most off-stack regressors sit behind exactly these edges, neighborhood recall won't beat stack-only → likely **NO-GO** (or scope to C/C++-only regressors).
- **`--calls-between` is class/namespace-scoped, depth/limit-bounded.** The CLI's `--calls-between SOURCE,TARGET` reasons over class/namespace pairs (not arbitrary function pairs), `--depth` defaults to 1 and `-l/--limit` to 50. Honest call-graph reach is therefore shallow unless the adapter raises depth/limit — and `calls-between` may simply return nothing for the function-level questions we want. Factor this into how the explorer phrases queries (favor `--calls-from`/`--calls-to` at raised `--depth`).
- **Revision drift.** `searchfox-cli` indexes ~tip of the git repo (github.com/mozilla-firefox/firefox), not the crash build node; the regressor patch *is itself* part of the diff between the crashed build and indexed source. A function may have moved/renamed/been removed at tip → false negatives in the recall check. Mitigate by picking recent nightly cases (days, not weeks) and resolving function identity via `--define`. Note `-R` cannot pin an arbitrary node — only `mozilla-central`/`mozilla-beta`/`mozilla-release`/esr/`comm-central`, no `autoland`.
- **Corpus availability.** The `clouseau`-alias corpus may be small, may lack `regressed_by`, or may be dominated by security bugs (signatures hidden). The corpus must be mined live from BMO (the `blocked='clouseau,{bugid}'` value is only written when a human actually files the prefilled bug). The 30-day DB retention means crashes age out — we rely on the BMO-frozen `cf_crash_signature` + `SuperSearch`, but old nightly UUIDs may no longer return processed data. Open question: minimum N for a credible go/no-go (target ≥6 off-stack cases).
- **"Reaches the regressor" definition.** Recall is over *function-name membership* in the neighborhood, not a validated call path — Phase 0 deliberately does not verify edges (that's the Skeptic, Phase 2). Risk of over-counting if name matching is loose; mitigate by canonicalizing names through `--define`.
- **Mapping `regressed_by` bug → exact changeset node.** A regressor bug can land multiple commits / get backed out and relanded. Open question: take all landed nodes, union their changed functions.
- **`searchfox-cli` not installed here** (`searchfox-cli not found`); **`libmozdata` not importable in this env** (only a source copy at `/home/calixte/rm.backup/dev/mozilla/git/libmozdata`). Both must be installed in the spike venv before steps 2/4.

## Acceptance criteria
- `spike/corpus.json` contains ≥6 curated nightly cases, each verified `off_stack` (regressor function absent from on-stack frame functions), with `regressor_nodes` and `signature` frozen.
- `python -m spike.run_spike --corpus spike/corpus.json` runs end-to-end against live `searchfox-cli` + Haiku 4.5 and writes `spike/results.json` with per-case results and the two aggregate recall numbers.
- Each case's trace shows the actual `searchfox-cli` commands executed (the exact `--calls-from`/`--calls-to`/`--calls-between`/`--define` flag invocations) and the symbols they returned (reproducible / inspectable).
- `spike/README.md` reports **stack-only recall vs. neighborhood recall** side by side and a one-line **GO** (neighborhood recall materially exceeds stack-only on off-stack cases, e.g. ≥ +30 points / reaches a clear majority) **or NO-GO** (no material gain — searchfox holes dominate), with the §7 blind spots that drove the result enumerated.
- Verify by hand on at least one **GO** case: open the cited searchfox neighborhood and confirm the regressor function is genuinely reachable from a stack frame (not a name collision).
- Nothing under `crashclouseau/`, `requirements.txt`, `config/`, `worker.py`, or `update.py` is modified (the spike is fully standalone).
